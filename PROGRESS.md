## Roadmap to a production bot (live orders, unattended)

Spec for the target: `ARCHITECTURE.md` (review of today's code and the ports-and-adapters design).
Everything above is a paper bot; live order placement does not exist and needs the phases below.
Order matters: a gate first (is there an edge?), then engineering foundations, then execution,
then operations, then a staged rollout. Phase 9b can run in parallel with 11 to 14 as long as the
forward test runs on a tagged, unchanged version.

| Phase | Scope | Exit criteria | Status |
|---|---|---|---|
| 9b | **Gate: forward paper test and rule decisions.** Run the 4-week test (`FORWARD_TEST.md`) on a tagged version. Settle open rules: break-even stop after T1, sizing on the real stop, Case 1/2 targets, arbiter priority, TradingView check of ORH/ORL and pivots, charge rates from a contract note, both-sides trap rules | Operational criteria in `FORWARD_TEST.md` met; written go/no-go on the strategy with the measured spread and slippage; rules frozen and versioned | [ ] |
| 10 | DhanHQ data adapter behind the existing data ports (candles, LTP, chain with delta, instruments), read-only capability | Contract tests pass against recorded Dhan responses; the same replay on Dhan and Groww data agrees; feed cross-check works | [ ] |
| 11 | **Delivery baseline.** Branch policy, tag the forward-test version, CI (ruff, mypy, tests, `pip-audit`), pre-commit, dependency lock, `import-linter` contracts, changelog | CI green on every PR; a tag reproduces the forward-test build | [x] Done locally (tag `v0.9.0`); GitHub settings and first CI run need your push, see log |
| 12 | **Architecture refactor** to ports and adapters: golden replay test first (the 54-day replay must reproduce trade for trade); split `PaperEngine` into position manager and `PaperVenue`; move orchestration out of `cli.py` and `LiveRunner` into application services; value types (`Price`, `Qty`, `Money`); error taxonomy; split config (strategy, runtime, risk) with the strategy hash recorded on every trade; structured logging with run IDs; fix test helpers into shared fixtures | Golden replay and all tests unchanged; layer contracts enforced in CI; no module over about 300 lines of mixed concerns | [ ] |
| 13 | **Persistence and event log.** Repository interfaces, versioned schema and migrations, normalized orders, fills, positions and signals, append-only event log with projections, PostgreSQL option, backups with a restore drill, daily archive of raw candles and option chains | Any past day can be rebuilt from events; migration and restore tested | [ ] |
| 14 | **Market-data hardening.** Streaming feed with tick-to-candle builder (REST as fallback and cross-check), automatic re-login and token refresh, holiday and special-session calendar, futures roll and expiry-day handling, data validation (gaps, outliers, stale quotes) | Live candle equals replay candle on recorded days; a 24-hour soak test with forced disconnects loses no candle | [ ] |
| 15 | **Order management and execution venues.** `OrderIntent` with idempotency keys, order state machine (new, sent, acknowledged, partial, filled, rejected, cancelled), broker order adapter (Groww first, Dhan later) with capability-scoped clients, order types and price protection, re-price or cancel policy, freeze-quantity splitting, broker-side stop orders, T1 partial and EOD square-off, broker position and funds reconciliation, `ShadowVenue` | Fake-broker tests with injected rejections, partial fills, disconnects and duplicate sends all end in a correct state; reconciliation detects every injected mismatch; paper path runs through the same order manager | [ ] |
| 16 | **Risk engine and kill switch.** Pre-trade gate (size, exposure, margin, liquidity and spread, price sanity, stale data), daily loss limit, loss-streak breaker, max trades, flatten-all command (file, Telegram, CLI), independent runtime supervisor, two-step live arming and pre-flight checks | Each limit has a test that trips it; the kill switch flattens within a set time in a failure-injection run | [ ] |
| 17 | **Deployment and observability.** Always-on host with static IP, service supervisor, scheduled start and stop, NTP, secrets handling, metrics, health endpoint, dead-man alert, second alert channel, log rotation, runbooks (restart, flatten, rollback, broker down), dev, staging and production environments | A week of unattended paper operation with no manual restart; alerts verified by drills | [ ] |
| 18 | **Compliance and audit.** Check broker and exchange rules for API and algo trading (static IP, algo tagging, order-rate limits, registration), retained audit trail, contract-note reconciliation, tax P&L report | Written compliance checklist signed off with the broker; audit export for any day | [ ] |
| 19 | **Shadow-live trial.** Real quotes and real option chain with simulated orders, compared with what real orders would have filled; measure slippage, spread and latency | At least 4 weeks; modelled versus shadow fills within agreed tolerance; costs known | [ ] |
| 20 | **Limited live.** 1 lot, tight daily loss limit, kill switch rehearsed, daily review; scale only after each stage is clean and a written go/no-go | Stage gates passed one by one; no unexplained difference between broker book and bot state | [ ] |
| 21 | Strategy backlog: both-sides trap, further tuning on real option data, new setups | Per item, validated on archived real data | [ ] |

Dependencies in short: 9b is the gate for everything past 15; 11 comes before 12; 12 and 13 come
